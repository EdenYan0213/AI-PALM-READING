三个阶段推进，每阶段结束 `mvn verify` 全绿 + 手动冒烟，分阶段提交。前端先行（你的重点），后端随后，工程化收尾。

## Phase 1 前端重构：Vite 多页应用（MPA）

**决策**：引入 Vite 但**不引入前端框架**（10 个页面均为原生 JS，页间是跳转关系，引 React/Vue 纯属负担）。`stitch_/frontend/` 改造为唯一的源码工程，`static/` 变成构建产物，双镜像手工同步从此消失。

### 1.1 脚手架
- `stitch_/frontend/` 新建 `package.json` + `vite.config.js`：vite 6、tailwindcss 3.4（含 forms/container-queries 插件，与现有 Play CDN 配置语义一致）、`material-symbols`、`@fontsource/plus-jakarta-sans`。
- 多页入口：11 个 HTML；`server.proxy` 把 `/api` 转发到 8080（本地 HMR 开发体验）；`build.outDir = ../backend/src/main/resources/static` + `emptyOutDir`。
- Maven 集成：`frontend-maven-plugin` 绑定 `generate-resources`（自动下载 node），`mvn package/verify` 自动构建前端，`-Dfrontend.skip=true` 逃生口；`static/` 加入 `.gitignore`。
- 产物迁移：7 张无引用的 screen.png → `frontend/design/`（不进 jar）；`static/MVP_PRD_V1.md` → `docs/`（与 docs/ 现有副本去重）；删除 `frontend/variants` 镜像。
- 测试夹具解耦：测试读的 `static/light_1/screen.png` 改为 `src/test/resources/fixtures/not-a-palm.png`。

### 1.2 页面重命名（内链全量更新，导航图已勘察完毕）
`light_1→home、light_2→capture、ai..._light→scanning（这个名字里有三个点，必须改）、trace_confirm→trace、light_3→report、cp_light→cp、weekly_quick→weekly、palm_calendar→calendar、record_detail→record-detail、monthly_energy→monthly`。

### 1.3 共享模块抽取（消灭约 1000 行复制粘贴）
- `src/shared/js/api.js`：API_BASE（删除全部 file:// 分支）、`request()`（超时/错误归一化为 `{code,message}`）、`postSse()`（SSE 解析器从 trace_confirm 提取）、`ensureUserId()`（5 份合一）、`track()`。
- `store.js`：9 个 localStorage key 收敛为带类型的唯一入口 + 生命周期（报告渲染后清 `capturedImage`、删除死键 `tracePayload`/`capturedMeta`、record-detail 不再从 URL query 收 userId）。
- `validate.js`：`validatePalmImage`（以 light_2 的 72px 严格版为准，消灭两份分叉）+ `compressDataUrl` + `isSkinTone`；**weekly_quick 接入压缩**（当前原图直存 localStorage 是配额炸弹）。
- `shareCard.js`：canvas 分享卡（light_3 与 monthly_energy 各 ~90 行合一）。
- `css/common.css` + `tailwind.config.js`：87 行 ×4 的 token 配置合一；glass-card/图标/壳层样式合一。
- 字体本地化后修复 6 个页面图标显示成英文单词的问题。

### 1.4 缺陷修复与 PRD 小缺口
- 8 张 googleusercontent 签名热链图下载为本地资源；light_1 死链（`./index.html`→404）与写死的"2024年5月20日"修复。
- report 页：稀有印记私域引导**弹层**（WECHAT_ID + 复制按钮，PRD §6.4 验收项）；report → cp 入口链接。
- 不做：CP 真实双人输入、广告 SDK（新功能，另行立项）。

## Phase 2 后端：分包 + 上帝类拆分（行为不变）

### 2.1 包结构（package-by-feature）
```
com.palmistrylab.api
├── common/      ExecutorConfig、WebCorsConfig、ApiRateLimitFilter(Clock 可注入)、全局异常
├── web/         SystemController(health,llm/ping)、PalmController(analyze/stream/unlock/rare-mark/validate)
│               RecordController(record/*)、CpController(cp/*)、MetricsController(track,metrics)
├── palm/        PalmAnalysisService(编排+三套缓存)、TraceGeometryAnalyzer(~270行纯几何)、
│               LocalPalmImageValidator(~150行AWT启发式)、ContentGuardrail(违禁词)、
│               PalmNarrativeWriter(提示词构建+JSON/文本输出解析)、SessionService、dto/
├── record/      PalmRecordService(周记录/日历/详情/笔记/月报)、entity/repo/投影、dto/
├── cp/          CpService、dto/
├── llm/         LlmClient(现 LlmClientService)、LlmCallException
├── perception/  PerceptionClient
├── media/       PhotoStorageService        ├── identity/ UserTokenService
└── metrics/     MetricsService、AppEvent 实体/仓库
```
ApiDtos.java（38 个 record）按特性拆进各 dto/ 包。SessionRecord/MonthlyReport 实体随领域归位。

### 2.2 拆分映射（PalmistryService 1717 行 → 8 个类，方法级映射已勘察）
几何解析组→TraceGeometryAnalyzer；图像启发式组→LocalPalmImageValidator；违禁词组→ContentGuardrail；prompt 拼接+parseJsonNode/extractJsonBlock/buildPalmOverviewFromText→PalmNarrativeWriter；analyzePalm 编排+缓存→PalmAnalysisService；weekly/calendar/detail/note/monthly→PalmRecordService；analyzeCp/unlockCpDeep/buildCpScore/buildComboName→CpService；trackEvent/metricsSummary→MetricsService。顺手修掉旧构造器 `photoStorageService==null` 的运行时空判断。

### 2.3 行为修复（拆分顺带）
- `getMonthlyReport` upsert 加 `@Transactional` + 仓库查询加悲观锁（消除并发重复月报行，全库零事务的现状就此打破）。
- ApiRateLimitFilter 的 `Clock` 改为可注入（现为硬编码，无法测试）。

### 2.4 测试
- 现有 30 个用例按新类拆分重组，全程保持绿色。
- 新增：TraceGeometryAnalyzer 纯函数用例（合成轨迹）、extractJsonBlock/ContentGuardrail、LocalPalmImageValidator、**LlmClientService 重试链与 SSE 解析**（MockRestServiceServer，当前 436 行零测试）、ApiRateLimitFilter（可注入 Clock 后）、核心端点控制器测试。

## 关键取舍（已按你的选择定）
