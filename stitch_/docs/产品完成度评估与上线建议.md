# 手相研究所 · 产品完成度评估与上线建议

评估日期：2026-09-09 ｜ 视角：资深产品经理 ｜ 基于 MVP_PRD_V1.0 验收标准

---

## 一、完成度总评

| 维度 | 完成度 | 说明 |
|------|--------|------|
| 后端 API | 95% | 14 个接口全部实现，含健康检查、单人/CP 分析、深度解锁、埋点、指标、周记录/日历/月报 |
| LLM 能力 | 80% | 已接 SiliconFlow（Kimi-K2.6 + GLM-5.1 兜底），有失败回退；但识别仍是规则+随机+文案拼装，图片并未真正被分析 |
| 前端页面 | 75% | 12 个页面变体齐备（含 V1.1 的校对模式、周签、月报、日历），但主流程 API 断链 |
| 商业化链路 | 60% | 广告解锁是模拟的（AD_REWARDED 直接返回 true），未接真实广告 SDK；私域导流只有弹层 |
| 数据与运营 | 70% | 埋点 + 指标看板可用；无漏斗细分、无防刷 |
| 可上线程度 | **约 50%** | 演示版已闭环；对真实用户上线还差关键几步（见下） |

**一句话结论：作为演示版（Demo）完成度约 85%，主流程闭环、文案引擎能跑；作为可对外的 MVP 完成度约 50%，卡在"单人主流程没接真实接口 + 会话不持久 + 无用户体系 + 合规空白"四件事上。**

## 二、P0 问题（上线前必须修）

### 1. 单人主流程 API 断链（最严重）
- `light_2`（拍照页）把照片存 localStorage 后直接跳 `ai..._light`（纯 setTimeout 动画），**全程没有调用 `/palm/validate-image` 和 `/palm/analyze`**。
- `light_3`（报告页）从 localStorage 读报告缓存，但没有任何页面写入过这个缓存 → 用户走主流程看到的报告只是兜底演示数据。
- 讽刺的是：**校对模式（trace_confirm）和 CP 流程都完整接入了 API**，说明后端没问题，纯粹是主流程前端没接线。PRD 验收标准第一条"可从首页完整走通单人流程"实际未达成。
- **修法**：把 trace_confirm 里调 `/palm/analyze` 的逻辑回移到 light_2/ai 页；分析页等待真实接口返回后再跳报告页。

### 2. 会话状态存内存
- `PalmistryService` 用 `ConcurrentHashMap` 存 SessionState，服务重启后所有 sessionId 失效 → 用户报告打不开、深度解锁失效、复发率归零。
- **修法**：SessionState 落库（已有 SessionRecordEntity，补上恢复逻辑）或换 Redis。

### 3. 记录模块无鉴权
- 周记录/日历/月报接口只凭前端传的 `userId` 查询，任何人可查任何人的数据。
- **修法**：至少做设备指纹/一次性 token；正式版做微信 openid 或手机号登录。

### 4. 合规空白
- 掌纹照片属于敏感个人信息（接近生物识别信息），需要单独同意 + 隐私政策。
- 玄学内容必须有**"仅供娱乐，不构成任何建议"**免责声明。
- 微信小程序/公众号明确禁止占卜算命类目——这直接决定上线渠道选择（见第四节）。

## 三、P1 问题与用户体验提升点

### 体验层
1. **分析等待体验**：PRD 写 3-5 秒，但真实 LLM 响应通常 8-15 秒。纯动画会让人怀疑卡死 → 建议真实进度条（分段轮询或 SSE），并保留趣味文案轮播。
2. **报告可回看**：现在重启即丢。接用户体系后做"我的手相报告"列表，这是留存的基本盘。
3. **分享链路是假的**：PRD 核心指标是分享率，但目前没有真正可传播的分享卡片。用 canvas 生成带结果摘要的图片 + 保存/转发，是增长引擎，优先级极高。
4. **首屏性能**：页面引用 Google Fonts（Plus Jakarta Sans + Material Symbols），国内访问极慢甚至失败 → 换国内 CDN 或本地字体。
5. **错误兜底**：LLM 失败有后端回退，但前端缺"重试"按钮和失败文案。
6. **免费层厚度**：免费总览只有 1 个区块，太薄会压低分享欲（用户没东西可晒）；太厚又伤广告解锁率。建议 A/B：免费给掌型+1 条主线亮点，深度内容给 3 分区。
7. **移动端适配**：所有页面需在微信内置浏览器（iOS/Android）实测，尤其摄像头调用和 file input 行为差异。

### 工程层
8. prod 配置 `ddl-auto: validate` 但没有 Flyway/Liquibase 迁移脚本，表结构变更会失控。
9. 没有 Dockerfile / 部署脚本，上线前补齐。
10. rate limit 已有（90 req/min），但埋点接口无防刷，指标会被污染。
11. `backend/logs/` 里有 5 个 JVM crash 日志（hs_err_pid*），建议排查内存配置并从 git 移除。
12. 仓库里 `target/` 编译产物和 `docs/`、`static/` 三处重复存放 PRD/页面，建议清理并统一单一样式源。

## 四、怎么上线：渠道选择（关键决策）

**硬约束先讲清楚：占卜算命属于国内平台明确限制的类目——**

| 渠道 | 可行性 | 说明 |
|------|--------|------|
| 微信小程序 | ❌ 基本不可行 | 平台规则明确禁止占卜、算命类目，审核必挂 |
| 公众号 H5（自建域名） | ⚠️ 可行但有风险 | 类目上不受小程序审核限制，但微信内传播若被举报存在封域名风险；需控制营销尺度 |
| 独立 H5 网站（ICP 备案） | ✅ 最稳的主路径 | 合规备案后，微信外渠道（群聊、抖音、小红书）引流，站内做私域沉淀 |
| 国内 App | ❌ 成本高且难上架 | 应用商店对占卜类审核极严，需特殊资质 |
| 海外版（英文/繁体） | ✅ 备选增长线 | 无类目限制，可上 App Store / Google Play，Deck 手相品类在海外有成熟付费市场 |

**推荐路线：独立 H5（备案域名）先行 → 私域（企微）沉淀 → 数据验证后再评估海外版。**

## 五、上线执行清单（按顺序）

### 阶段 0：修核心链路（1 周内）
1. 打通 light_2 → analyze → light_3 真实 API 链路（P0-1）
2. SessionState 持久化（P0-2）
3. 页面部署到后端 static 统一托管，删掉 variants 里的演示跳转导航

### 阶段 1：可部署（3-5 天）
4. Dockerfile + docker-compose（app + MySQL）
5. 云服务器（轻量 2C4G 起步）+ MySQL + HTTPS（Caddy/Nginx + Let's Encrypt）
6. 域名 + ICP 备案（周期约 2-3 周，**建议立刻启动，与开发并行**）
7. LLM API Key 走环境变量（已支持），配置用量告警防刷爆

### 阶段 2：合规与体验（与备案并行）
8. 首页 + 报告页加"仅供娱乐"免责声明与年龄提示
9. 隐私政策 + 掌纹照片上传单独同意弹窗
10. Google Fonts 替换为国内 CDN
11. 分享卡片真实生成（canvas 出图）
12. admin_metrics 加访问口令，不能裸奔在公网

### 阶段 3：灰度放量
13. 内测：50-100 人（朋友圈/群），盯 PRD 四大指标：分享率、广告解锁率、私域转化率、CP 发起率
14. 基准预期参考：这类轻娱乐产品分享率 15%+、广告解锁率 8-12% 算健康；低于 5% 说明免费层/文案有问题
15. 数据达标后再考虑投放大号内容引流（抖音/小红书"赛博玄学"话题）
